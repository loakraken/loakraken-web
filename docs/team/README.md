# LOAKraken 웹 — 작업 규칙 (모든 에이전트 세션 공통)

이 파일은 저장소에서 작업하는 모든 세션(로컬 팀·클라우드 팀)이 **작업을 시작할 때 먼저 읽는** 규칙이다(루트 CLAUDE.md는 각자 PC의 로컬 파일이라 저장소에 두지 않는다). 원본은 사용자 PC의 옵시디언 볼트(`30 PM/사용자 지적 회귀 점검표.md`, `30 PM/PM 검토 절차.md`, `30 PM/팀별 스킬 배정.md`)에 있다. 볼트에 접근할 수 없는 세션도 이 파일만 읽으면 같은 기준으로 일할 수 있게 핵심을 옮겼다. 규칙이 바뀌면 PM 총괄이 이 파일도 고친다. 볼트 핵심 문서 사본은 같은 폴더의 `vault/`에 있다.

모든 설명·커밋·PR·이슈는 한국어로 쓴다.

## 제품 방향

- 로스트아크 정보 사이트다. 목표 사이트들의 **기능과 정보는 모두 흡수**하고, **디자인은 우리 것**으로 만든다. 디자인 기준은 21st.dev·bencho.dev 계열이고 아이콘은 Iconsax(`components/ui/icons.tsx`)만 쓴다.
- **화면에 다른 사이트 이름을 쓰지 않는다.** UI, API 메시지, 패치노트 모두 해당한다.
- 화면에 '출처', 공지 번호, 확인일을 표시하지 않는다. 데이터 파일 안의 `source`·`checkedAt`은 내부 기록으로 유지한다.
- 계산값은 확실한 값만 보인다. 원인 모를 불일치는 P0다. "다를 수 있음" 같은 애매한 단서 문구는 금지한다.
- **현금 거래(RMT) 시세·환산·입력 칸은 금지**한다. 골드↔현금은 공식 크리스탈 경로만 쓴다.
- 처리정지(개인정보) 캐릭터는 기록·랭킹·인기·통계·길드·자동완성·검색 엔진에서 제외한다. 화면에는 일반 미기록 캐릭터와 똑같이 보여야 한다.

## 사용자 지적 회귀 점검표 (어기면 P1, 병합 안 됨)

| # | 규칙 |
|---|---|
| A1 | 네이티브 `<select>` 금지. `components/ui/select.tsx`를 쓴다 |
| A2 | 탭은 `PillTabs`만 쓴다. `role="tablist"`를 직접 만들지 않는다 |
| A3 | 스크롤 영역은 사이트 공통 스크롤바를 쓴다 |
| A4·A5 | 라이트·딤·다크(+시스템) 4테마를 **모든 경로**가 따른다. 테마 연타에도 색이 섞이지 않는다 |
| A6·A7 | 첫 로드와 조작 중 레이아웃 이동(CLS)은 0이다. 1280px·360px 모두 해당한다. 불러오는 동안 크기를 유지한다 |
| A8 | 보이는 숫자는 항상 지금 조건의 값이다. 바뀌는 중에는 이전 값을 흐리게(aria-busy) 둔다. `keepPreviousData`는 `isPlaceholderData` 표시와 함께만 쓴다 |
| A9 | 숫자 카운트업·모핑 금지. 최종값을 한 번에 보인다 |
| A10 | 반복 애니메이션은 계속 재생하고, 사용자가 멈출 수 있어야 한다. prefers-reduced-motion을 지킨다 |
| A11 | hover 배경은 공통 틴트 토큰만 쓴다. 하드코딩 색 금지, 글자 대비 4.5:1 이상 |
| A13 | 화면에 사이트 이름·'출처'를 넣지 않는다(예외: /contact의 공식 API 표기, 능력치 출처 분해) |
| A14 | 다른 탭·화면으로 이동하면 맨 위로 간다. 필터 변경만 위치를 유지한다 |
| A15 | 팝업·툴팁은 고정 헤더·탭 바를 가리지 않는다 |
| A16·A17 | 공개된 도구 경로는 모두 헤더 메뉴에 있다. 데스크톱 메뉴 패널은 여러 열이다 |
| A18 | 누르는 아이콘은 16px 이상, 대비 3:1 이상이다 |
| A19 | 같은 일을 하는 컨트롤을 한 화면에 두 개 두지 않는다 |
| A20 | 요청 없는 단축키를 추가하지 않는다 |
| A21·A22 | 값이 안 바뀌거나 계산하지 않는 항목은 이유를 화면에 보인다. 우리가 만든 용어는 설명과 함께 쓴다 |
| A23 | 구할 수 없는 값을 사용자에게 입력시키지 않는다 |
| A24 | 기능을 없애면 문구·상태·링크까지 전부 지운다 |
| A25 | sticky는 관련 묶음 단위로 건다 |
| A28 | 정보는 목표 사이트와 같게 한다. PR에 체크리스트 ID(L·K·M·N 번호)를 인용한다 |
| A31·A32 | 배지·칩·숫자·등락 묶음은 줄바꿈하지 않는다(nowrap, flex: none). 본문은 `word-break: keep-all`. 링크 단어를 쪼개지 않는다 |

## 소유 경계 (같은 파일을 두 팀이 동시에 고치지 않는다)

- **프론트 1팀**: `components/character/**`, `components/site/**`(헤더·검색), 캐릭터 경로
- **프론트 2팀**: `components/market/**`, `components/stats/**`, `components/home/**`, 새 사이트 기능 폴더(멀티서치·떠돌이 상인 등)
- **성장 도구팀**: `components/tools/**`, `lib/tools/**`(데이터 파일은 게임 데이터팀과 협의)
- **디자인 시스템팀**: `components/ui/**`, 토큰·전역 스타일, `scripts/check-regressions.mjs`
- **게임 데이터팀**: `lib/tools/data/*.json`의 값
- **QA**: `e2e/**`. 각 팀은 자기 기능의 e2e를 같은 PR에 추가해도 된다.
- 경계 밖 변경이 필요하면 PR 본문의 '요청' 칸에 적는다.

## PR 규칙

- 이슈·PR 제목은 `[FEAT|FIX|DESIGN|REFACTOR|TEST|DOCS|CHORE] 한글`이다. 라벨을 달고 GitHub Projects #1에 연결한다. 기준 브랜치는 `develop`이다.
- **도구 표기 금지**: 커밋·PR·이슈에 Claude·Codex·"Generated with"·`Co-Authored-By` 같은 표기를 넣지 않는다.
- **PR 본문 필수 칸**
  - 체크리스트 ID
  - **회귀 점검표 확인**: 해당 번호와 결과
  - **사용한 스킬**: 고친 점 포함
  - 화면 변경은 3테마 × 1280·360 캡처
  - 요청
- 병합은 검토 PM이 한다. 웹은 PM-프론트다. 작성 팀은 직접 병합하지 않는다.
- e2e는 목 백엔드(`tests/mock-backend.mjs`)만 쓴다. 공식 API·외부 사이트를 호출하지 않는다. 자세한 실행법은 `e2e/README.md`에 있다.

## 스킬 (화면 PR 필수)

- `web-design-guidelines`, `frontend-a11y`는 매번 쓴다.
- 새 화면은 설계 전에 `design-taste-frontend`·`ui-ux-pro-max`, 구현 후에 `impeccable`(audit·polish)을 쓴다.
- 서버 데이터 화면은 `tanstack-query-best-practices`, e2e는 `playwright-best-practices`를 쓴다.
- 외부 HTML·사용자 입력을 표시하면 `security-audit`의 CLIENT-SIDE를 참고한다.
- 스킬 제안과 위 규칙이 충돌하면 **위 규칙이 우선**한다.
